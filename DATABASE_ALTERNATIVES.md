# 🗄️ Альтернативные варианты размещения базы данных

Документ описывает различные варианты размещения базы данных для проекта Lavsit Textile, включая возможность использования встроенной БД.

---

## ❌ Почему SQLite не работает на Vercel

**SQLite НЕ МОЖЕТ быть использован на Vercel** по следующим причинам:

1. **Файловая система только для чтения**: Vercel serverless функции имеют файловую систему только для чтения (кроме `/tmp`)
2. **Нет постоянного хранилища**: SQLite требует файл на диске, который должен сохраняться между запросами
3. **Ограничения serverless**: Каждая функция выполняется в изолированном окружении без постоянного состояния

**Вывод:** Для продакшена на Vercel **ОБЯЗАТЕЛЬНО** нужна внешняя база данных (PostgreSQL, MySQL и т.д.)

## ✅ Рекомендуемые варианты для Vercel

### 1. Supabase (текущий выбор) ⭐

**Преимущества:**
- ✅ Бесплатный тариф с 500MB БД
- ✅ Автоматические бэкапы
- ✅ Встроенная аутентификация
- ✅ REST API из коробки
- ✅ Connection Pooling для serverless
- ✅ Простая интеграция с Prisma

**Недостатки:**
- ⚠️ Требует внешний сервис
- ⚠️ Ограничения на бесплатном тарифе

**Настройка:**
```env
DATABASE_URL="postgresql://postgres:[PASSWORD]@aws-0-us-east-1.pooler.supabase.com:6543/postgres?pgbouncer=true&schema=public"
NEXT_PUBLIC_SUPABASE_URL="https://[PROJECT-ID].supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="[ANON-KEY]"
```

**Важно:** Используйте **Connection Pooler** (порт 6543), а НЕ прямое подключение (порт 5432)!

### 2. Vercel Postgres ⭐⭐⭐ (ЛУЧШИЙ ВАРИАНТ)

**Преимущества:**
- ✅ Интеграция напрямую с Vercel
- ✅ Автоматическая настройка переменных окружения
- ✅ Оптимизирован для serverless
- ✅ Бесплатный тариф: 256MB БД, 60 часов compute
- ✅ Автоматические бэкапы
- ✅ Нет проблем с connection pooling

**Недостатки:**
- ⚠️ Привязан к Vercel (нельзя использовать локально напрямую)

**Настройка:**
1. Перейдите в Vercel Dashboard → ваш проект
2. **Storage** → **Create Database** → **Postgres**
3. После создания, `DATABASE_URL` автоматически добавится в Environment Variables
4. Готово! Никаких дополнительных настроек не требуется

**Стоимость:**
- **Hobby (бесплатно)**: 256MB, 60 часов compute/месяц
- **Pro ($20/мес)**: 8GB, 512 часов compute/месяц

## 💡 Можно ли разместить БД внутри проекта?

### ❌ НЕТ для продакшена на Vercel

Как уже упоминалось, **SQLite НЕ РАБОТАЕТ на Vercel** из-за ограничений serverless окружения.

### ✅ ДА для локальной разработки

Для **локальной разработки** можно использовать SQLite:

```prisma
// prisma/schema.prisma (локальная версия)
datasource db {
  provider = "sqlite"
  url      = "file:./dev.db"
}
```

**Преимущества SQLite для разработки:**
- ✅ Не требует внешних сервисов
- ✅ Быстрая настройка
- ✅ Файл БД в проекте (удобно для разработки)
- ✅ Не нужен интернет

**Как переключаться между SQLite и PostgreSQL:**

1. **Локально**: Используйте SQLite (файл `prisma/dev.db`)
2. **На Vercel**: Используйте PostgreSQL (через переменную `DATABASE_URL`)

Скрипт `scripts/prepare-vercel-schema.js` автоматически переключает schema при деплое на Vercel.

---

## 🔧 Рекомендуемая конфигурация

### Для разработки (локально):
```env
# .env.local
DATABASE_URL="file:./prisma/dev.db"
```

Используйте SQLite для быстрой разработки.

### Для продакшена (Vercel):
```env
# Vercel Environment Variables
DATABASE_URL="postgresql://postgres:[PASSWORD]@[HOST]:[PORT]/postgres?schema=public"
```

Используйте один из вариантов PostgreSQL выше.

## 🚀 Рекомендация

### Для нового проекта:
**Используйте Vercel Postgres** - это самый простой и оптимальный вариант для Vercel.

### Для текущего проекта:
Если Supabase уже настроен, можно продолжить использовать его, но **обязательно используйте Connection Pooler** (порт 6543), а не прямое подключение!

---

## ⚠️ Важные замечания

1. **Connection Pooling обязателен** для serverless окружения (Vercel)
2. **НЕ используйте прямое подключение** (порт 5432) на Vercel - это не работает!
3. **SQLite можно использовать только локально** для разработки
4. **Всегда проверяйте** формат `DATABASE_URL` перед деплоем
