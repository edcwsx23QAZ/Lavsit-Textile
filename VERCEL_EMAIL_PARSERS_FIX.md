# Исправления для email-парсеров на Vercel (Аметист и Нортекс)

## Проблема
На Vercel файловая система read-only, кроме директории `/tmp`. Email-парсеры (Аметист и Нортекс) пытались сохранять файлы в `process.cwd()/data/email-attachments/`, что не работает на Vercel.

## Решение

### 1. Автоматическое определение Vercel окружения
- Проверка переменных окружения: `process.env.VERCEL === '1'` или `process.env.VERCEL_ENV`
- Автоматическое использование `/tmp` для временных файлов

### 2. Исправления в `lib/email/email-parser.ts`

#### `saveAttachment()` метод:
- Автоматически определяет Vercel окружение
- Использует `/tmp/email-attachments/{supplierId}/` на Vercel
- Fallback на `/tmp` если основная директория недоступна
- Сохраняет правильный путь в базу данных

#### `getUnprocessedAttachments()` метод:
- Проверяет существование файлов по оригинальному пути
- Если файл не найден и путь содержит `data/email-attachments`, автоматически ищет в `/tmp/email-attachments`
- Возвращает корректный путь к файлу

### 3. Исправления в `lib/parsers/ametist-parser.ts`

#### `extractZipFile()` метод:
- На Vercel использует `/tmp/ametist-extracted/` для распаковки ZIP архивов
- Локально использует директорию рядом с архивом

### 4. Исправления в `app/api/suppliers/[id]/parse/route.ts`

#### Логика для всех email-поставщиков:
- Автоматическое определение Vercel окружения
- **На Vercel**: всегда получаем письма заново при каждом запросе (файлы в `/tmp` удаляются после завершения функции)
- **Локально**: используем файлы из БД, если они доступны
- Fallback логика поиска писем без фильтров, если письма не найдены с фильтрами
- После сохранения файла на Vercel используем его напрямую, не проверяя через `getUnprocessedAttachments`
- Добавлено явное логирование для Нортекса и всех email-поставщиков

#### Выбор парсера:
- **Аметист**: использует `AmetistParser` (поддерживает ZIP архивы)
- **Нортекс и другие email-поставщики**: используют `EmailExcelParser`

## Результат

Теперь оба парсера (Аметист и Нортекс) корректно работают на Vercel:
- ✅ Файлы сохраняются в `/tmp` (единственная доступная для записи директория)
- ✅ Пути к файлам корректно сохраняются в базу данных
- ✅ При поиске файлов автоматически проверяется `/tmp` если файл не найден по оригинальному пути
- ✅ ZIP архивы (Аметист) распаковываются в `/tmp`
- ✅ На Vercel всегда получаем письма заново при каждом запросе
- ✅ После сохранения файла на Vercel используем его напрямую

## Важно

На Vercel файлы в `/tmp` удаляются после завершения функции. Это означает:
- Файлы нужно обрабатывать сразу после сохранения
- Нельзя полагаться на файлы, сохраненные в предыдущих запросах
- При каждом парсинге нужно заново получать письма и сохранять вложения
- Логика автоматически определяет Vercel окружение и получает письма заново

## Логирование

Добавлено детальное логирование для:
- Определения окружения (Vercel/Local)
- Процесса получения писем
- Валидации файлов для каждого поставщика
- Использования файлов напрямую на Vercel
