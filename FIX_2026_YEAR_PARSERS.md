# Исправление парсеров для работы с 2026 годом

## Проблема

При переходе на 2026 год некоторые парсеры перестали работать из-за:
1. Захардкоженных дат 2025 года в URL
2. Неправильного парсинга 2-значных годов (YY) - интерпретация "26" как 1926 вместо 2026

## Исправления

### 1. Артекс (arteks-parser.ts)

**Проблема:** В URL была захардкожена дата `25.12.2025-2.xlsx`

**Исправление:**
- Заменен URL на плейсхолдер: `DD.MM.YYYY-2.xlsx`
- Обновлена логика парсера для поддержки плейсхолдера
- Парсер теперь автоматически ищет актуальный файл, перебирая даты от текущей до 30 дней назад

**Файлы:**
- `scripts/init-suppliers.ts`
- `app/suppliers/page.tsx`
- `app/api/suppliers/route.ts`
- `app/api/suppliers/init/route.ts`
- `lib/parsers/arteks-parser.ts`

### 2. Эгида (egida-parser.ts)

**Проверка:** Парсер использует `formatDateForUrl` который берет последние 2 цифры года через `slice(-2)`. Для 2026 года это будет "26", что правильно.

**Статус:** ✅ Работает корректно

### 3. TextileNova (textilenova-parser.ts)

**Проблема:** Парсинг 2-значных годов мог интерпретировать "26" как 2026, но логика была неоптимальной.

**Исправление:**
- Обновлена логика парсинга 2-значных годов
- Теперь используется текущий год как ориентир
- Год "26" в 2026 году интерпретируется как 2026

**Файлы:**
- `lib/parsers/textilenova-parser.ts`

### 4. Аметист (ametist-parser.ts)

**Проверка:** Парсер использует `parseDate` из `base-parser.ts` для парсинга дат. Не использует даты в URL.

**Статус:** ✅ Должен работать корректно (использует общий парсер дат)

### 5. Нортекс (email-excel-parser.ts)

**Проверка:** Парсер использует `parseDate` из `base-parser.ts` для парсинга дат. Не использует даты в URL.

**Статус:** ✅ Должен работать корректно (использует общий парсер дат)

### 6. Tex.Group (texgroup-parser.ts)

**Проверка:** Парсер не использует даты в URL и не парсит даты из данных.

**Статус:** ✅ Нет проблем с датами

## Общие исправления

### Парсинг 2-значных годов

Для правильной интерпретации 2-значных годов (YY) в 2026 году:
- Год "26" интерпретируется как 2026 (текущий век)
- Используется текущий год как ориентир
- Логика работает для всех парсеров, использующих `parseDate` из `base-parser.ts`

## Проверка

После деплоя проверьте работу парсеров:
1. **Артекс** - должен находить актуальный файл с датой 2026 года
2. **Эгида** - должен находить актуальный файл с датой в формате DD.MM.26
3. **TextileNova** - должен правильно парсить даты из Excel с годом 2026
4. **Аметист, Нортекс** - должны правильно парсить даты с годом 2026
5. **Tex.Group** - должен работать как обычно
