# Настройка локального сервера парсеров

Этот документ описывает настройку локального сервера парсеров для использования в качестве fallback механизма при ошибках на Vercel.

## Обзор

Локальный сервер парсеров работает как резервный вариант: если парсинг на Vercel не удался, система автоматически обращается к локальному серверу. Ошибка показывается пользователю только если оба варианта (Vercel и локальный) не сработали.

## Установка зависимостей

Убедитесь, что установлены все зависимости:

```bash
npm install
```

Сервер использует следующие зависимости:
- `express` - веб-сервер
- `cors` - поддержка CORS
- `axios` - HTTP клиент
- `cheerio` - парсинг HTML
- `xlsx` - парсинг Excel файлов
- `exceljs` - работа с Excel файлами

## Запуск локального сервера

### Базовый запуск

```bash
npm run local-parser
```

Сервер запустится на порту 4002 (по умолчанию) или на порту, указанном в переменной окружения `LOCAL_PARSER_PORT`.

### Режим разработки (с автоперезагрузкой)

```bash
npm run local-parser:dev
```

## Настройка порта

Порт можно изменить через переменную окружения:

```bash
LOCAL_PARSER_PORT=5000 npm run local-parser
```

Или создать файл `.env.local`:

```
LOCAL_PARSER_PORT=5000
```

## Настройка доступа из Vercel

Для того, чтобы Vercel мог обращаться к локальному серверу, нужно настроить туннель. Есть несколько вариантов:

### Вариант 1: ngrok (рекомендуется)

1. Установите ngrok: https://ngrok.com/download
2. Запустите локальный сервер парсеров
3. В отдельном терминале запустите ngrok:

```bash
ngrok http 4002
```

4. Скопируйте HTTPS URL (например, `https://xxxx.ngrok.io`)
5. Добавьте переменную окружения в Vercel Dashboard:
   - Имя: `LOCAL_PARSER_URL`
   - Значение: `https://xxxx.ngrok.io`

### Вариант 2: Cloudflare Tunnel

1. Установите Cloudflare Tunnel
2. Настройте туннель для порта 4002
3. Добавьте URL туннеля в переменную окружения `LOCAL_PARSER_URL` в Vercel

### Вариант 3: Локальный туннель (localtunnel)

```bash
npx localtunnel --port 4002
```

Скопируйте URL и добавьте в `LOCAL_PARSER_URL` в Vercel.

## Проверка работы

### Health Check

Проверьте доступность сервера:

```bash
curl http://localhost:4002/health
```

Должен вернуться JSON с информацией о статусе и списком поддерживаемых парсеров.

### Тестовый запрос парсинга

```bash
curl -X POST http://localhost:4002/parse \
  -H "Content-Type: application/json" \
  -d '{
    "parserName": "TextileNovaParser",
    "supplierId": "test-id",
    "supplierName": "TextileNova",
    "url": "https://example.com",
    "rules": {
      "columnMappings": {
        "collection": 0,
        "color": 0
      }
    }
  }'
```

## Как работает fallback механизм

1. При запросе парсинга система сначала пытается выполнить парсинг на Vercel
2. Если возникает ошибка, система автоматически проверяет доступность локального сервера через health check
3. Если локальный сервер доступен, система отправляет тот же запрос на локальный сервер
4. Если локальный сервер тоже возвращает ошибку, система возвращает исходную ошибку с Vercel
5. Пользователь видит ошибку только если оба варианта не сработали

## Логирование

Все действия логируются в консоль:

- Попытка парсинга на Vercel
- Ошибка на Vercel (с деталями)
- Попытка обращения к локальному парсеру
- Результат работы локального парсера (успех/ошибка)
- Финальный результат (успех или ошибка после всех попыток)

## Устранение неполадок

### Сервер не запускается

- Проверьте, что порт не занят другим процессом
- Убедитесь, что все зависимости установлены (`npm install`)
- Проверьте логи на наличие ошибок

### Vercel не может подключиться к локальному серверу

- Убедитесь, что туннель (ngrok/localtunnel) запущен
- Проверьте, что переменная окружения `LOCAL_PARSER_URL` правильно настроена в Vercel
- Убедитесь, что URL в `LOCAL_PARSER_URL` использует HTTPS (для ngrok)
- Проверьте health check: `curl https://your-tunnel-url.ngrok.io/health`

### Локальный парсер возвращает ошибки

- Проверьте логи локального сервера
- Убедитесь, что локальный сервер имеет доступ к тем же URL, что и Vercel
- Проверьте, что правила парсинга корректны

## Безопасность

⚠️ **Важно**: Локальный сервер не имеет встроенной аутентификации. Рекомендуется:

1. Использовать ngrok с аутентификацией или Cloudflare Tunnel
2. Ограничить доступ к туннелю только для Vercel IP адресов (если возможно)
3. Не использовать локальный сервер в продакшене без дополнительной защиты

## Переменные окружения

- `LOCAL_PARSER_PORT` - порт для локального сервера (по умолчанию 4002)
- `LOCAL_PARSER_URL` - URL локального сервера для использования в Vercel (должен быть настроен в Vercel Dashboard)
